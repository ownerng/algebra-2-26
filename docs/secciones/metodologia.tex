\section{Metodología}

\subsection{Arquitectura del sistema}

El sistema tiene tres partes: el prototipo físico, que mide; el firmware del
ESP32, que controla el barrido y envía las lecturas, y una interfaz web, que
hace los cálculos matriciales y dibuja el mapa
(Figura~\ref{fig:arquitectura}). Las lecturas viajan por el cable USB como
texto en formato JSON, una línea por medición, por ejemplo
\verb|{"r":523,"theta":84}|.

\subsection{Prototipo físico}

El prototipo usa los componentes de la Tabla~\ref{tab:materiales}, montados
sobre una protoboard de 400 puntos según la Figura~\ref{fig:protoboard}. El
sensor se alimenta con 3,3 V y se comunica por el bus I\textsuperscript{2}C
(GPIO 21 para SDA y GPIO 22 para SCL); sus cuatro cables van directo a los pines
del ESP32. El servomotor se alimenta con los 5 V del pin VIN a través del riel
inferior de la protoboard y recibe la señal de control por el GPIO 13. Entre
ese riel de 5 V y tierra se conecta un condensador electrolítico de 1000 µF
para absorber los picos de corriente del servo, que de otro modo pueden
reiniciar el microcontrolador. La Figura~\ref{fig:esquematico} muestra el mismo
circuito como esquemático.

En el diseño mecánico (Figura~\ref{fig:mecanico}), el servo va fijo a una base
rígida y el sensor se monta sobre el brazo del servo con un soporte en L, con
el lente lo más cerca posible del eje de giro y a la altura de los objetos que
se quieren detectar. La distancia $d$ entre el eje y el lente se suma a cada
lectura (Figura~\ref{fig:geometria}); en la simulación se usó $d = 15$ mm. La
guía de armado completa, con la lista de pasos y el color de cada cable, está
en el archivo \texttt{docs/montaje-lidar.html} del repositorio del proyecto.

\subsection{Firmware}

El firmware, escrito en C++ con el entorno de Arduino, mueve el servo de
$0^\circ$ a $180^\circ$ y de regreso en pasos de $2^\circ$. En cada paso espera
35 ms a que el servo se estabilice, toma una medición del sensor y envía la
línea JSON correspondiente. Cuando no hay objetos dentro del alcance envía
$r=-1$, para que la interfaz pueda mover el haz aunque no dibuje un punto. El
firmware también acepta tres comandos de un carácter desde la interfaz:
iniciar, pausar y centrar el servo en $90^\circ$.

\subsection{Procesamiento matemático}

Cada lectura se procesa en dos pasos, que corresponden a los dos productos
matriciales del marco teórico. Primero, la lectura se lleva al sistema local
del aparato:
\begin{equation}
\vect{p}_L = R(\theta)\begin{bmatrix} r + d\\ 0\end{bmatrix}.
\end{equation}
Después, el punto local se lleva al sistema global con la matriz homogénea de
la posición desde la que se midió:
\begin{equation}
\begin{bmatrix}\vect{p}_G\\ 1\end{bmatrix}
= T(\alpha, d_x, d_y)\begin{bmatrix}\vect{p}_L\\ 1\end{bmatrix}.
\end{equation}
La primera posición define el sistema global, de modo que para ella
$\alpha=0$, $d_x=d_y=0$ y $T=I$. Para la segunda posición, $d_x$, $d_y$ y
$\alpha$ se miden con cinta métrica y transportador después de mover el
aparato. Si el servo gira en sentido contrario al esperado, la interfaz permite
usar $180^\circ-\theta$ en lugar de $\theta$, lo que equivale a una reflexión
del sistema local.

Las funciones de álgebra lineal (rotación, matriz homogénea, inversa y
productos) se programaron directamente en TypeScript, sin bibliotecas de
cálculo, para que el código refleje las ecuaciones del marco teórico.

\subsection{Interfaz web}

La interfaz se construyó con React y TypeScript, se empaqueta con Bun y se
ejecuta en el navegador. Recibe los datos del ESP32 a través de un puente USB
(\texttt{web/puente.ts}) que reenvía cada línea del puerto serie por WebSocket,
lo que permite usarla en cualquier navegador; si el puente no está activo,
usa la API Web Serial de Chrome. Está organizada para que quien la mira sepa
qué se está calculando y por qué:

\begin{itemize}
\item Una guía de cuatro pasos en la parte superior (conectar, escanear desde
la posición 1, mover el aparato y escanear desde la posición 2) que se marca
sola a medida que se completa cada paso.
\item El radar 2D, dibujado con Canvas, con escala de 30~cm, 60~cm o 1,2~m, y
una vista 3D hecha con Three.js en la que el mapa del plano se levanta en
altura para facilitar su lectura. Esta vista 3D es una visualización: el
sensor mide en un solo plano.
\item Un panel del prototipo que dibuja en vista superior el servo, el sensor y
el haz, y gira con cada lectura.
\item Un panel donde se indica desde qué posición se mide y cuánto se movió el
aparato entre las dos posiciones ($d_x$, $d_y$ y $\alpha$). Esos tres números
forman la matriz $T$; al cambiarlos, el mapa se recalcula al instante, lo que
permite ver cómo una pose mal medida desarma el mapa.
\item Un cuaderno, escrito con KaTeX, que desglosa el cálculo de una lectura en
cinco pasos: la suma $r+d$, la matriz $R(\theta)$ con sus valores, el producto
fila por columna con la comprobación de la norma, el producto por $T$ y el
punto resultante. Un botón permite congelar el cálculo en una lectura para
explicarla con calma; esa lectura queda marcada en el radar.
\end{itemize}

Con el botón \textit{Simular prototipo}, la interfaz usa el simulador descrito
en el protocolo experimental y superpone en el radar la habitación real, para
comparar lo que mide el escáner con lo que debería medir. El código del
proyecto (firmware, interfaz, pruebas y este informe) está en
\url{https://github.com/ownerng/algebra-2-26}.

\subsection{Protocolo experimental}

Para medir la precisión de la fusión se necesita conocer la posición real de
cada objeto, algo que no es posible con mediciones a mano. Por eso los
experimentos cuantitativos se hicieron en un entorno simulado: una habitación
virtual con paredes, las patas de una mesa y de una silla, una caja y una
papelera. El simulador lanza un rayo en la dirección de cada ángulo, calcula la
intersección con los objetos y devuelve la distancia con el mismo formato JSON
que el firmware. Se agregó ruido uniforme de $\pm(3 + 0{,}01\,r)$ mm y una
probabilidad de 3\,\% de perder la lectura. El generador de números aleatorios
usa una semilla fija, de modo que los resultados son reproducibles.

Se realizaron tres experimentos:
\begin{enumerate}
\item Escaneo desde dos posiciones y fusión con la pose correcta.
\item Fusión con una pose errónea ($8^\circ$ de error en $\alpha$ y 80 mm en
$d_x$), para observar el efecto en el mapa.
\item Barrido del error en $\alpha$ entre $0^\circ$ y $20^\circ$ sin ruido del
sensor, comparando el error medio de registro con la predicción teórica.
\end{enumerate}
Además, se verificaron numéricamente las propiedades de las matrices
implementadas y se escribieron siete pruebas automáticas para las funciones
de álgebra lineal y su concordancia con el simulador.
