\section{Metodología}

\subsection{Arquitectura del sistema}

El sistema tiene tres partes: el prototipo físico, que mide; el firmware del
ESP32, que controla el barrido y envía las lecturas, y una interfaz web, que
hace los cálculos matriciales y dibuja el mapa
(Figura~\ref{fig:arquitectura}). Las lecturas viajan por el cable USB como
texto en formato JSON, una línea por medición, por ejemplo
\verb|{"r":523,"theta":84}|.

\subsection{Prototipo físico}

El prototipo usa los componentes de la Tabla~\ref{tab:materiales}. El sensor
se alimenta con 3,3 V y se comunica por el bus I\textsuperscript{2}C (GPIO 21
para SDA y GPIO 22 para SCL). El servomotor se alimenta con los 5 V del pin VIN
y recibe la señal de control por el GPIO 13. Entre las líneas de 5 V y tierra
se conectó un condensador electrolítico de 1000 µF para absorber los picos de
corriente del servo, que de otro modo pueden reiniciar el microcontrolador.
El sensor va fijado sobre el brazo del servo con un soporte en L, con el lente
lo más cerca posible del eje de giro. La distancia $d$ entre el eje y el lente
se midió y se suma a cada lectura (Figura~\ref{fig:geometria}).

\subsection{Firmware}

El firmware, escrito en C++ con el entorno de Arduino, mueve el servo de
$0^\circ$ a $180^\circ$ y de regreso en pasos de $2^\circ$. En cada paso espera
35 ms a que el servo se estabilice, toma una medición del sensor y envía la
línea JSON correspondiente. Cuando no hay objetos dentro del alcance envía
$r=-1$, para que la interfaz pueda mover el haz aunque no dibuje un punto. El
firmware también acepta tres comandos de un carácter desde la interfaz:
iniciar, pausar y centrar el servo en $90^\circ$.

\subsection{Procesamiento matemático}

Cada lectura se procesa en dos pasos, que corresponden a los dos productos
matriciales del marco teórico. Primero, la lectura se lleva al sistema local
del aparato:
\begin{equation}
\vect{p}_L = R(\theta)\begin{bmatrix} r + d\\ 0\end{bmatrix}.
\end{equation}
Después, el punto local se lleva al sistema global con la matriz homogénea de
la posición desde la que se midió:
\begin{equation}
\begin{bmatrix}\vect{p}_G\\ 1\end{bmatrix}
= T(\alpha, d_x, d_y)\begin{bmatrix}\vect{p}_L\\ 1\end{bmatrix}.
\end{equation}
La primera posición define el sistema global, de modo que para ella
$\alpha=0$, $d_x=d_y=0$ y $T=I$. Para la segunda posición, $d_x$, $d_y$ y
$\alpha$ se miden con cinta métrica y transportador después de mover el
aparato. Si el servo gira en sentido contrario al esperado, la interfaz permite
usar $180^\circ-\theta$ en lugar de $\theta$, lo que equivale a una reflexión
del sistema local.

Las funciones de álgebra lineal (rotación, matriz homogénea, inversa y
productos) se programaron directamente en JavaScript, sin bibliotecas de
cálculo, para que el código refleje las ecuaciones del marco teórico.

\subsection{Interfaz web}

La interfaz se ejecuta en el navegador y recibe los datos con la API Web
Serial. Tiene una vista de radar 2D dibujada con Canvas y una vista 3D hecha con
la biblioteca Three.js, en la que el mapa del plano se levanta en altura para
facilitar su lectura. Esta vista 3D es una visualización: el sensor mide en un
solo plano. Junto al mapa, un panel muestra la multiplicación de matrices de la
lectura más reciente con sus valores numéricos, la matriz homogénea de la
posición activa y las columnas de $R(\alpha)$ como ejes de la segunda
posición. Al modificar $d_x$, $d_y$ o $\alpha$, el mapa se recalcula al
instante, lo que permite ver cómo una pose mal medida desarma el mapa.

\subsection{Protocolo experimental}

Para medir la precisión de la fusión se necesita conocer la posición real de
cada objeto, algo que no es posible con mediciones a mano. Por eso los
experimentos cuantitativos se hicieron en un entorno simulado: una habitación
virtual con paredes, las patas de una mesa y de una silla, una caja y una
papelera. El simulador lanza un rayo en la dirección de cada ángulo, calcula la
intersección con los objetos y devuelve la distancia con el mismo formato JSON
que el firmware. Se agregó ruido uniforme de $\pm(3 + 0{,}01\,r)$ mm y una
probabilidad de 3\,\% de perder la lectura. El generador de números aleatorios
usa una semilla fija, de modo que los resultados son reproducibles.

Se realizaron tres experimentos:
\begin{enumerate}
\item Escaneo desde dos posiciones y fusión con la pose correcta.
\item Fusión con una pose errónea ($8^\circ$ de error en $\alpha$ y 80 mm en
$d_x$), para observar el efecto en el mapa.
\item Barrido del error en $\alpha$ entre $0^\circ$ y $20^\circ$ sin ruido del
sensor, comparando el error medio de registro con la predicción teórica.
\end{enumerate}
Además, se verificaron numéricamente las propiedades de las matrices
implementadas y se escribieron pruebas automáticas para cada función de
álgebra lineal.
